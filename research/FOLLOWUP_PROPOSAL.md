## 1. 用一个例子说明新任务

图片中有人骑自行车，穿红色雨衣，车筐里有花，后座坐着小孩。

- 已有描述 A：“一个人在骑自行车。” 看衣服、车筐或后座都可能补充事实。
- 已有描述 B：“穿红雨衣的人骑着车筐装花的自行车。” 衣服和车筐的信息已覆盖；后座可能更值得看。
- 把 B 换成同义句，选择应基本不变。
- 如果后座已经描述充分，再看同一处应很少增加信息，模型可以停止。

旧任务主要看删掉一个短语后分数是否变化。新任务问：**在当前已知信息下，执行一次实际的视觉观察，能增加多少有证据支持的事实？** 正确的后续区域可能属于已经提到的同一个物体。

## 2. 研究问题与可能的新意

**H1：** 同一图片不同描述下，后续区域的实际价值会改变；这种变化不能由静态显著性或“物体提没提到”充分解释。

**H2：** 从实际观察收益训练的选择器，能在相同 captioner、候选区域和输出长度下，超过强提示规划器与语义覆盖 baseline。

**H3：** 成对的 caption 上下文监督能改善“新增事实后改变选择、同义改写后保持选择”的行为，并迁移到新图片、新初始 caption 来源及另一种 reader。

潜在贡献是经过验证的 **caption 条件下的观察价值学习**，尤其是已提及实体的未覆盖属性/关系。可能需要的技术是跨 caption 的动作价值监督和显式已知事实状态。上下文 bandit、pairwise ranking、覆盖惩罚和 STOP 都是已有技术；使用它们本身不是新意。

### 与近邻的边界

| 近邻 | 我们必须证明的额外内容 |
|---|---|
| [CompreCap](https://github.com/LuFan31/CompreCap) / [CapProbe](https://arxiv.org/abs/2608.11074) | 从评价静态 caption，推进到预测并执行后续观察；不能只新增一套 coverage 指标 |
| [CapRL](https://github.com/InternLM/CapRL) / [CCCaption](https://arxiv.org/abs/2602.21655) / [ClaimDiff-RL](https://arxiv.org/abs/2605.20278) | 固定内容生成器，单独测区域选择是否提供额外收益；caption 的 QA/正确性奖励沿用前人思想并引用 |
| [AdaptVision](https://github.com/AdaptVision/AdaptVision) | 以已有描述中尚未覆盖的事实为目标；系统验证同图换描述后的动作价值与跨 reader 泛化；预算化裁剪本身不新 |
| [高分辨率遗漏对象补全](https://arxiv.org/html/2510.27164v1) | 不能只补新物体；需要在已提及实体属性、关系及重复观察上超过该规则式流程 |
| [SC-Captioner](https://github.com/zl2048/SC-Captioner) | 增益来自证据选择机制，不只是更多自我纠正调用 |

这些差异目前是待验证假设。若强基线实现后不存在实质区别，就不把该方案包装成“首次”或直接扩大为投稿论文。

## 3. 严格定义输入、动作和收益

### 输入与动作

状态 `s = (低分辨率全局图, 已有描述 T, 已获取区域及观察结果 H)`。候选区域来自同一固定自动 proposal 生成器，并包含规则 grid、少量有空间关系的区域组合及 STOP。第一阶段固定 12–16 个候选，先做一步选择；多步最多 3 次作为后续扩展。

GT 框只作诊断上界。若某关系需同时看两个实体，允许一个联合区域动作，并计入实际像素/token 成本。不能让某方法额外免费看到更清晰的目标，也不能用测试标注生成只对我们有利的候选。

固定观察器 `D` 读取所选 crop，生成有视觉依据的局部描述。第一版冻结它的权重和提示；最终输出为原始描述加简短补充。合并器只能表达已观察到的事实。主要数据用正确但不完整的 T；初始 caption 含错时的修复另设压力测试，避免混淆补充与纠错。

### 事实与评估

对每张评测图建立独立核验的事实集合 `F`，覆盖对象、属性、动作和关系，并记录支持区域。令 `E(T)` 为 T 已蕴含的事实。事实匹配必须保留实体指代，不能把一个人的红衣服算到另一人身上。

主要质量端点为 `(|E(T_after) ∩ F| − |E(T_before) ∩ F|) / |F|`，按图像平均；同时报告新增正确事实数、未覆盖事实恢复率、错误新增事实数和重复表达率。已有描述已覆盖全部标注事实时，应报告 STOP 行为，不用零分母的恢复率。

标注集合不是整个世界的穷尽：输出中未在 F 出现的事实不能直接算幻觉，要回看图像核验。评测集需对各方法输出的新增事实做盲法补充核验，并保持方法之间一致的规则。

辅助端点是固定文本 reader 在隐藏视觉问题上的表现增量。Reader 只看 T 和已获得的描述；选择器、观察器不能看到测试问题或答案。使用纯文本可猜中对照、开放式/弃答题、多个 reader 及人工核验，防止 QA 分数增长只是猜测或 reward overfitting。

### 动作监督

训练时对开发图枚举候选动作，固定 D，记录实际观察结果。动作标签为：新增正确覆盖收益、错误新增风险、重复信息以及测得的成本。标注/教师可在训练时评价所有候选；部署选择时只允许查看低成本全局特征、T、H 和候选坐标/特征。

不能先对所有区域跑昂贵 caption，再把“最好的区域选择”声称为低成本预测；这只能作为全信息诊断或计入全部费用的强 baseline。

## 4. 方法：先直接监督，再决定是否需要 RL

1. **最强可解释 baseline。** 对区域生成事实，做文本蕴含/去重，按新增有依据事实排序。公开完整成本，作为性能与数据质量基准。
2. **直接收益选择器。** 用视觉 patch tokens、区域位置、已有描述和历史状态，训练小型 cross-attention 模块或 VLM LoRA，预测每个动作的覆盖收益和错误风险。用实际收益回归与同一状态下的动作排序监督，校准 STOP。
3. **成对上下文监督。** 同一图片提供覆盖内容不同但流畅的 T：已补充目标事实后，其动作收益应按实际标签下降；同义改写应保持价值；无关事实更新只对受影响的事实集合约束。监督真实收益变化，不强制一个区域只能对应一个事实。
4. **状态更新。** 将已获得的事实写回状态，避免重复区域反复获得相同奖励。测事实记忆相对仅存 crop ID 的价值。
5. **多步扩展。** 只有一步选择已有优势、且二步/三步上界明显优于贪心时，再使用 offline trajectory ranking 或策略优化。关系协同可能违反收益递减，不宣称未经证明的 submodular 最优保证。

训练奖励可组合收益、错误和成本，但论文必须分别画出质量、错误和总成本，不能只用一个自行调权的总分证明成功。权重在验证集确定。

## 5. 数据计划

### 第一阶段：发现是否真的存在空间

新取 300–500 张开发图片，排除旧 350 张及近重复。每图生成/人工改写 4 个流畅描述状态：简略、已覆盖局部细节、同义改写、覆盖较充分。保留自然初始 caption，不全部依赖人工设定的删词题。

每图准备约 12–16 个候选，枚举一步实际收益；抽取一部分图做两步组合。由两位审核者独立核验至少 100 张的事实与状态差异，裁定分歧，公布对象/属性/关系的分别一致性。自动审查用于筛候选，不当人工真值。

这里需要约 `图数 × 状态数 × 候选数` 个动作评价，例如 500 × 4 × 12 = 24,000 个状态动作对。若 D 不依赖 T，可以共享 crop 描述，但上下文相关收益仍需分别算。人工成本、teacher 推理和候选缓存都应测量。

### 课程版本

建议起点为 3,000 张训练、500 张验证、500 张未碰过的测试图，规模随开发集配对方差调整。每图 2–4 个描述状态，按图像而不是 caption 划分。覆盖对象与属性；关系作为明示的扩展子集。至少两种初始 caption 来源，主测试使用自动区域；GT 框只作上界。

使用 Visual Genome 等可获得的区域/属性/关系标注作训练起点，但其缺标不是“事实不存在”。CompreCap 可作外部评估。COCO、VG 与相关 caption 数据可能重叠，按图像 ID、文件 hash 与近重复检查隔离。所有已用于选方法的外部样本以后归为开发数据。

### 论文版本

如果课程验证成功，扩大到约 20,000–50,000 张训练图、独立验证集和至少两个隔离的测试域；主测试总量建议从 2,000 张起，依据最小有意义效应和图像级方差做功效规划。不要把一个图片的数十个问题当数十个独立样本。

建设 500–1,000 张有双人核验的事实/区域测试子集，覆盖自然图片与另一种视觉领域；补充同一图片多描述状态。可用 [CaptionQA](https://github.com/bronyayang/CaptionQA) 公开部分作为 reader 外测，但完整评测需按其发布机制处理；CapProbe 当前不能作为必须可下载的依赖。

## 6. 必须打过的 baseline

所有方法共享初始 T、观察器、候选区域规则和输出长度限制；比较总费用而不只数 crop。

| Baseline | 回答的问题 |
|---|---|
| 原始 T，不增加观察 | 有没有实际新增收益 |
| 同一个强 VLM 直接看全图补写；低/高分辨率，匹配输出长度 | 区域选择是不是比直接问模型更有用 |
| 固定 grid / area / random / inverse cosine / n-gram | 是否超过简单启发式 |
| 物体遗漏检测 → crop → 补充（按前作实现并注明 adaptation） | 是否超越已经存在的遗漏物体流程 |
| 所有区域 caption + NLI/覆盖排序 | 语义规则是否已经解决；完整推理费用计入 |
| 同一基础 VLM 的提示式下一步 crop planner | 是否只是更好的 prompting 或多调用几次 |
| AdaptVision 式 planner，任务匹配后评估 | 是否优于既有主动视觉机制；适配结果不冒充论文原指标 |
| 无上下文 / 不更新状态 / 无成对监督的学习器 | 收益是否来自所提机制 |
| 同候选同预算的 oracle；所有候选观察 | 是否存在上界空间，哪些失败来自识别而非选择 |

CapRL/SC-Captioner 等可作为强生成器比较，但主要因果归因实验固定 D。否则“更强 captioner 赢了”不能证明选择器有效。每个方法报告 selector、proposal、VLM、reader 的调用与耗时；训练成本与部署成本分开。

## 7. 第一批实验及明确的决策标准

以下数值是拟议的研究决策阈值，须在新开发数据评测前固定；不是预报结果。

| 实验 | 内容 | 推进条件 |
|---|---|---|
| E0：定义与审核 | 流畅多 caption、事实覆盖、实例指代、候选可见性 | 随机审核中关键标签达约 90% 可裁定一致；不达标先修标签 |
| E1：收益上界 | 枚举候选观察，比较 oracle 与最强现实 baseline | 相同费用范围下 oracle 的覆盖增量领先约 10 个百分点，且配对区间支持实质空间；观察器本身能读出缺失细节 |
| E2：上下文是否必要 | 同图换 caption、同义改写、已覆盖事实、近饱和描述 | 自动区域的最优动作确实随信息覆盖变化；不能只在人工构造样本有效 |
| E3：直接监督能否学习 | 三个 seed；强规则/提示 baseline；逐步增加训练样本 | 验证集上约 3–5 个百分点增益、图像 bootstrap CI 下界 > 0，错误率不恶化；一次扩展数据后仍失败则停止该学习路线 |
| E4：锁定确认 | 固定模型、参数、预算和评测，运行 500 图独立测试 | 主指标相对预指定最强 baseline 正向；人工子集方向一致，初始 caption 来源外推仍有效 |
| E5：投稿扩展 | 双域/双 reader/至少两 backbone、三步、自动区域、成本曲线 | 增益广泛成立；在已提及实体属性/关系上有明确机制解释 |

E1 可先报告未惩罚的纯质量上界，再按费用画 Pareto 曲线；不要用不同方法各自挑选的成本权重定义“获胜”。实例缺标、纯文字猜中或无效区域不能用来人为拉大空间。

主要比较建议固定新增文字 96 tokens、一步观察；扩展为 48/96/192 tokens 和 1/2/3 次观察曲线。用统一 tokenizer 计比较长度，同时报告各模型实际 token 与运行时间。阈值和这些预算只是初始方案，运行前根据任务与人类可读性确定，不能事后选最有利的一点。

错误率的非劣界限应提前设定（例如新增事实错误率最多上升 2 个百分点，CI 上界也需满足），不能只看平均没升。确认失败时保留全部表格、说明下一步变更，用新的测试数据确认，不继续刷同一测试集。

## 8. 为什么这比继续调旧 MLP 更有希望

- 标签来自有依据的事实与实际动作结果，直接对应想达到的效果。
- 可先测 oracle，确认“知道怎么选”确实有收益。
- 使用能识别属性/关系的现有 VLM，减少把模型感知不足与选择策略混在一起。
- 课程阶段一步选择和固定生成器就能产生可解释结果；多步 RL 是后续问题。
- 新意围绕可验证的条件性与价值预测，能够用删除模块、交换 caption 和固定 reader 检验。

这些改动改善研究设计，不保证一定赢。若直接全图补写或强提示 planner 已达到 oracle 附近，应明确放弃该路线。若只有更大生成器带来提高，则可以报告应用改进，但不足以满足方法 novelty 的目标。

## 9. HPC 与实施顺序

研究规模不按旧小时数压缩。按三类作业组织：数据/标注与 CPU 评估，批量教师和 baseline 推理，选择器训练。使用可用兼容 GPU；多卡优先分片独立推理，再考虑训练并行。模型、分辨率和序列长度通过实际显存/吞吐测量决定，不声称 L4 单卡能承载任意训练。

可先用已有公开 3B–8B VLM 作固定观察器与 planner，选择器用 token 特征模块或 LoRA；更大的教师或全参/RL训练是待 profiling 的选择。公开 repo 的默认多卡配置不直接当本集群能执行的命令。CapRL/AdaptVision 等训练环境放在独立环境，避免破坏旧 pilot。

每个动作输出带图像/状态/region ID、模型 revision、prompt hash、token 数、耗时与失败原因；跨重试缓存。GPU 计算期间每 5 秒采样，优化 batching、decode workers 与排队；不要为了占用制造无用计算。遵守最新项目指令，不手动取消或释放现有分配，由服务器管理回收。

### 代码状态与下一次实现清单

现有 `pilot/next_round.py` 只对应已经跑完的旧冻结实验，不能用它声称新方案已经实现。本次产出为研究判断与提案。

新路线先实现 E0–E2：统一数据 schema → caption/fact 标注适配器 → 自动候选与可见性 → 固定 crop observer 与缓存 → 强 baseline → 全候选收益/oracle → 盲评与图像 bootstrap 报告。E1/E2 有空间后再实现 selector 训练；之后才需要序列策略。申请 GPU 前应完成对应阶段代码与 CPU preflight。

建议产物 schema：`image_id, split, context_id, initial_caption, candidate_id, bbox_or_region_set, observed_text, supported_fact_ids, covered_fact_ids_before/after, invalid_claims, cost, provenance`。Gold 事实/收益与模型可见输入分开存放；测试答案不得进入 selector 的 prompt、缓存键所指内容或特征。

## 10. 达到不同研究阶段需要什么

**课程完成标准：** 一套可复现的新任务实现，至少一个有明确动机的方法改进，相对强 baseline 的独立测试正向效果，人工核验，两个关键消融以及清楚的前作差异。当前旧结果还不满足用户要求。

**CVPR 级目标：** 证明已知方法未解决的具体结构性困难；方法在同图不同 caption、未见属性/关系、自然描述以及自动区域下均有收益；控制生成器/成本/监督量后优势仍在；提供可靠测试数据、源码和失败分析。只有数据规模或一个显著数字仍不够。

**TPAMI 等长期目标：** 在基础贡献成立后，研究多步状态、关系联合证据、跨 reader/领域迁移、停止校准和质量—成本规律。期刊工作的深化应提供额外机制与系统证据，不是把会议实验再增加几个数据集。

## 最终建议

停止旧 MLP 作为主线，正式评估新的“已有描述条件下的视觉观察价值”任务。先完成 E0–E2 的数据与强 baseline/oracle 比较，再决定训练。若空间成立，它提供了课程正向结果和进一步研究的合理路径；若不成立，换到新的题目，不把已经成熟的 caption refinement 包装成 novelty。
